ollamacode-cli

How ocode works

A terminal coding agent that runs on your own Ollama models. This page follows one request from your keyboard to the model, through the tools, and back.

1

System overview

Everything runs in one Node process started by bin/cli.js. The chat UI hands each request to the agent core, which loops between the model and the tools until the model answers in plain text.

2

One turn

A turn is a loop in src/agent/turn/turn.ts. Each step asks the model once. A reply with only text is the answer and ends the turn; a reply with tool calls runs them and goes round again, unless a guard stops it.

  • Before the loop, executeTurn settles the mode (agent, plan or review), narrows the task scope, and decides whether this is a replan. Plan mode explores read-only in its own context and presents a plan for you to approve.
  • The closing answer asks once more with no tools so a stopped turn still says what it did. Some small models answer with a tool call anyway; then the turn ends without text and the reporter says what ran.
  • The reporter (src/cli/chat/turn/turn-reporter.ts) shows the answer and at most one status line: done, paused, out of steps, or waiting on a background job.
3

A tool call, step by step

Every call settles in one place, settleCall in src/agent/turn/tool-calls.ts. From there it is written into history for the model and shown to you as a tool line.

  • Discovery. Only a few cheap tools have their full schema on every request. The rest are listed by name; the model calls load_tools to get a schema before first use. MCP tools join the same way.
  • Severity on screen. A result with status PARTIAL (work that went part of the way, such as a subagent that ran out of steps) shows as a yellow ⚠ line, not a red error. The model still reads it as unfinished.

5

Subagents

The delegate_task tool hands a self-contained task to a child turn. The child is the same runTurn loop with its own empty history and a narrower set of tools. It cannot see the parent's conversation, so everything it needs goes in the task.

RoleToolsStepsTimeTold to
researchread-only + web_search, web_fetch205 minAnswer with sources; change nothing
reviewread-only205 minReport problems with file and line
codingall its parent has258 minMake the change, then build or test
testall its parent has158 minRun or write tests; touch only test files

Subagents are on by default; "subagents": false in the agent config turns them off.

6

Background jobs

A command that keeps going (a dev server, or a slow first build) would hold the turn hostage. ocode starts it, waits a few seconds, and moves it to the background if it has not finished. When it ends, the result is shown to you and handed to the agent in a new turn.
